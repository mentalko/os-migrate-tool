# os-migrate-tool

Перенос Ubuntu → CachyOS через внешний SSD. Скрипты живут на SSD
(`os-migrate-tool/`), при каждом прогоне самообновляются там же.
Общий код (хелперы + проверка окружения) — в `lib.sh`. TUI — `tui.py`
на curses (stdlib python, без установки): alt-screen, скролл длинных
списков, переживает resize; при недоступном python3 — bash-fallback в
lib.sh. На FAT/exFAT/NTFS-SSD запускать `bash pack.sh` / `bash unpack.sh`.

## Команды

### Упаковка (Ubuntu)

```bash
./pack.sh            # или bash pack.sh
./pack-kitty.sh      # то же в отдельном окне kitty; лог сессии в /tmp/omt-pack-*.ts
                     # (агент читает лог при падении), код выхода — .rc
```

Интерактивно:
1. Выбор SSD — сканируются смонтированные диски, показываются
   устройство, метка, точка монтирования, свободное место.
2. Двухуровневый чеклист (tui.py на curses): группы цианом, подпункты dim,
   курсор инверсией; группы помечены ▸ (свёрнута) / ▾ (развёрнута).
   → — раскрыть группу и нырнуть в первый подпункт; ← — свернуть, а с
   подпункта — вернуться к родительской группе; Tab — раскрыть/свернуть
   все группы разом. Нижняя панель под курсором: полное описание пункта,
   путь и автосводка «Внутри:» (крупнейшие подпапки с размерами), живой
   итог объёма в шапке, q — отмена в любой момент.
   Пути и описания — `inventory.yaml` (группы `group_<имя>` с секциями);
   дефолты галочек — `selection.yaml` (дерево повторяет чеклист:
   `group_<имя>.on` + вложенные пути; ON-подпункт едет даже внутри
   выключенной группы).
3. Шаг подтверждения: выбранные пути построчно с размерами, сырой объём,
   оценка tar.gz, свободное место и таблица планируемых архивов. Только
   после явного `y` — упаковка.
4. `--dry-run` — полный прогон без записи на SSD, вывод как у реального.

### Распаковка (CachyOS)

```bash
./unpack.sh                          # полностью интерактивно
./unpack.sh all                      # все компоненты прогона
./unpack.sh --packages --appimages   # флаги можно комбинировать
./unpack.sh --dry-run dotfiles.tar.gz extra.tar.gz   # отчёт без изменений
```

Режимы:
- `--packages` — сверяет `packages/apt-list.txt` с `mapping.tsv`;
  ставит через pacman/yay только записанное; не найденное → отчёт
  `missing-mapping.txt`, молча ничего не ставится.
- `--appimages` — копирует в `~/Applications`, `chmod +x`.
- `--dotfiles` / `--agents` / `--browsers` / `--data` — распаковка tar.gz.
  Конфликт: если верхнеуровневые пути архива уже есть в $HOME — один
  вопрос на архив: перезаписать / пропустить / backup (*.bak-premigrate).
- Перед браузерами скрипт спросит про пароль старого keyring.

## Шаг подтверждения

Перед упаковкой pack.sh показывает: список выбранных путей построчно с размерами,
сырой объём, оценку после tar.gz, **свободное место на SSD** и таблицу
«Планируемые архивы» (каждый архив и его размер). Только после явного `y` — упаковка.

## Общий диск двух систем (не скрипт, руками)

Если «SSD» — не внешний диск, а раздел, общий между Ubuntu и CachyOS (dual-boot):
- монтируй его на обеих системах, `os-migrate-tool/` живёт там же;
- большие несжимаемые данные (Documents, Pictures) можно переносить вообще без
  архива — прямым копированием на общий раздел, unpack.sh тогда только докладывает
  недостающее; архивировать обязательно только то, что теряет метаданные на FAT/exFAT;
- архивы tar.gz на общем ext4-разделе сохраняют права и симлинки — предпочтительно.

## Конфиг на новой системе

Конфигурация — два YAML-файла (парсит `conf.py`, мини-YAML на stdlib):
**`inventory.yaml`** — полный инвентарь: группы `group_<имя>` с секциями
(`home`/`config`/`sessions` у агентов, `dirs`/`files`, `paths`) и `desc:`;
**`selection.yaml`** — галочки по умолчанию, дерево повторяет чеклист
(`group_<имя>.on` + вложенные пути `путь: true/false`).
При инициализации на новой системе ИИ-агент обязан:
1. проверить/актуализировать пути в `inventory.yaml` под новую систему (они могут
   отличаться: версии агентов, новые каталоги сессий — особое внимание
   `group_agents.sessions`; старые значения могут быть неактуальны, пример:
   бэкап `agent-sessions-20261013_18443/logs/sessions` — путь умер);
2. пересмотреть `selection.yaml` под новую систему (что тяжёлое/опциональное);
3. новый путь → сразу добавить описание в `desc:` inventory.yaml
   (`путь: что в каталоге`), иначе в чеклисте будет только путь;
4. не хардкодить пути в pack.sh/unpack.sh — только правкой конфигов.

## Правила

- `mapping.tsv` — единственный источник истины для установки пакетов.
  Формат: `ubuntu_pkg<TAB>status<TAB>install_cmd<TAB>notes`;
  status ∈ {native, aur, skip}. Нет строки → только в отчёт.
- Названия прогонов: `<дата>_<исходная-ос>` (берётся из /etc/os-release),
  чтобы бэкапы до/после переезда не смешались.
- Перед распаковкой браузеров убедиться, что пользователь помнит пароль
  старого keyring — иначе пароли в профиле не откроются.
- Внимание: `agents.tar.gz` содержит креды агентов (~/.zcode/cli/credentials.json,
  .codex/auth.json, .claude и т.п.) — SSD с бэкапом держать при себе/шифровать.
- Прямые ссылки на файлы отчёта давать после каждого шага.
