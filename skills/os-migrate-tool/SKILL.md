# os-migrate-tool

Перенос Ubuntu ↔ CachyOS через внешний SSD (универсальный пакер linux,
сейчас arch ↔ debian). Первый шаг unpack — определение ТИПА системы по
os-release (arch/debian); не удалось — выбор из списка (переопределяется
`OMT_SYS_TYPE`). Тип выбирает команды установки из `configs/mapping.toml`. Скрипты живут на SSD
(`os-migrate-tool/`), при каждом прогоне самообновляются там же.
Общий код (хелперы + проверка окружения) — в `src/lib.sh`. TUI — `src/tui.py`
на curses (stdlib python, без установки): alt-screen, скролл длинных
списков, переживает resize; при недоступном python3 — bash-fallback в
lib.sh. На FAT/exFAT/NTFS-SSD запускать `bash pack.sh` / `bash unpack.sh`.

## Рабочий цикл агента (как помогать)

1. **Уточни задачу**: что пользователь хочет запаковать или распаковать.
2. **Определи тип системы**: `arch` / `debian` — по os-release текущей машины
   (ID/ID_LIKE). От типа зависят команды установки в `configs/mapping.toml`
   (`arch = …` / `debian = …`) и подсказки по пакетному менеджеру (pacman/yay
   против apt). Не определился — unpack сам спросит; тесты — `OMT_SYS_TYPE`.
3. **Сверь конфиги с задачей** (правится только `configs/`, детали —
   configs/README.md):
   - «запаковать X» → есть ли X в `inventory.yaml` (нужная группа/секция);
     нет — добавь путь + описание в `desc:`;
   - «X должен ехать по умолчанию» → `selection.yaml` (`group_<имя>.on`
     или точечный вложенный путь; ON-подпункт едет даже в OFF-группе);
   - «не пакуй Y» → `exclude_dirs.yaml` (шаблон без хвостового `/`) или
     off в selection;
   - «программу Z ставить на новой системе» → `mapping.toml`
     `[programs.<npm|uv|pipx|bin>.<тул]` с командами `arch`/`debian` и `url`.
4. **Запусти**: `bash pack.sh [--dry-run] [--no-compress]` — интерактивно в
   текущем терминале, или `bash pack-kitty.sh [флаги]` — отдельное окно kitty
   с логом сессии (`/tmp/omt-pack-*.ts`, код выхода `.rc`) — агент читает лог
   при падении и разбирается сам.
5. **Распаковка**: `unpack.sh [сегменты|all]` на целевой системе; тип
   определяется первым шагом; без аргументов — TUI-дерево (сегмент → путь →
   подпуть, маркеры `●` цель уже есть / `○` будет создана); программы
   спрашиваются пошагово (меню вариантов под систему); в конце — блок ссылок
   «скачать/установить вручную».
6. **Отчёты**: давать ссылки на `paths.tsv` (что→куда), `manifest.txt`
   (sha256+дерево), `missing-mapping.txt`.

## Команды

### Упаковка (Ubuntu)

```bash
./pack.sh            # или bash pack.sh
./pack.sh --no-compress   # бандл .tar без сжатия: быстрее, выборочная
                      # распаковка мгновенная; на SSD ~raw объём
./pack-kitty.sh      # то же в отдельном окне kitty; лог сессии в /tmp/omt-pack-*.ts
                     # (агент читает лог при падении), код выхода — .rc
```

Интерактивно:
1. Выбор SSD — сканируются смонтированные диски, показываются
   устройство, метка, точка монтирования, свободное место.
2. Трёхуровневый чеклист (tui.py на curses): группы цианом, подпункты dim,
   курсор инверсией; группы помечены ▸ (свёрнута) / ▾ (развёрнута).
   → — раскрыть группу и нырнуть в первый подпункт; ← — свернуть, а с
   подпункта — вернуться к родительской группе; Tab — раскрыть/свернуть
   все группы разом. Нижняя панель под курсором: полное описание пункта,
   путь и автосводка «Внутри:» (крупнейшие подпапки с размерами), живой
   итог объёма в шапке, q — отмена в любой момент.
   Пути и описания — `configs/inventory.yaml` (группы `group_<имя>` с секциями);
   дефолты галочек — `configs/selection.yaml` (дерево повторяет чеклист:
   `group_<имя>.on` + вложенные пути; ON-подпункт едет даже внутри
   выключенной группы).
3. Шаг подтверждения: выбранные пути построчно с размерами, сырой объём,
   оценка, свободное место и таблица сегментов бандла. Если формат не задан
   флагом — вопрос «с сжатием или без» (оценки обоих вариантов). Только
   после явного `y` — упаковка. В процессе — однострочный прогресс-бар
   `▓▓▓░░░` на каждый сегмент.
4. `--dry-run` — полный прогон без записи на SSD, вывод как у реального.

### Распаковка (CachyOS)

```bash
./unpack.sh                          # TUI-дерево: что именно возвращать
./unpack.sh all                      # все сегменты бандла, без дерева
./unpack.sh dotfiles extra           # по именам сегментов (или --dotfiles --extra)
./unpack.sh --dry-run agents         # отчёт без изменений
```
Прогон = ОДИН бандл `archives/<дата>_<ос>.tar.gz` (сегменты компонентов
внутри, под своими каталогами, + резерв `meta/` с paths.tsv) + `.meta/`
(manifest.txt, paths.tsv). Список содержимого с размерами читается один
проходом (`tar -tv`), выбранные домашние пути извлекаются ОДНИМ проходом
tar. Потерянный `.meta/` восстанавливается unpack'ом из резервного
сегмента автоматически.

Без аргументов — TUI-дерево выбора (как чеклист pack): сегмент →
верхнеуровневый путь → подпуть 2-го уровня; `→`/`←` раскрыть/свернуть,
`Tab` — все списки разом, `пробел` — галочка. Маркеры существования цели:
`●` жёлтый — уже есть в $HOME (будет перезаписан), `○` зелёный — будет
создан; в hint под курсором — состояние, путь и «Внутри:» (что лежит там
сейчас). Выбраны все верхнеуровневые пути → сегмент целиком.

Режимы:
- `packages` — сверяет `packages/apt-list.txt` из бандла с `configs/mapping.toml`
  под ТИП системы; ставит только записанное; не найденное → отчёт
  `missing-mapping.txt`, молча ничего не ставится.
- `appimages` — копирует в `~/Applications`, `chmod +x`.
- `dotfiles` / `agents` / `browsers` / `data` / … — извлечение выбранных путей.
  Конфликт (выбранная цель уже есть в $HOME) — один вопрос на сегмент:
  перезаписать / backup (`*.bak-premigrate`) / keep (докатить только
  несуществующее) / пропустить.
- Перед браузерами скрипт спросит про пароль старого keyring.

## Шаг подтверждения

Перед упаковкой pack.sh показывает: выбранные пути построчно с размерами,
сырой объём, оценку, свободное место на SSD и таблицу сегментов бандла.
Если формат не задан флагом (`--no-compress` / `--compress`) — вопрос
«с сжатием или без» с оценками обоих вариантов. Только после явного `y` —
упаковка; в процессе — однострочный прогресс-бар на каждый сегмент.

## Общий диск двух систем (не скрипт, руками)

Если «SSD» — не внешний диск, а раздел, общий между Ubuntu и CachyOS (dual-boot):
- монтируй его на обеих системах, `os-migrate-tool/` живёт там же;
- большие несжимаемые данные (Documents, Pictures) можно переносить вообще без
  архива — прямым копированием на общий раздел, unpack.sh тогда только докладывает
  недостающее; архивировать обязательно только то, что теряет метаданные на FAT/exFAT;
- архивы tar.gz на общем ext4-разделе сохраняют права и симлинки — предпочтительно.

## Конфиг на новой системе

Конфигурация — три YAML-файла в `configs/` (парсит `src/conf.py`, мини-YAML на stdlib):
**`configs/inventory.yaml`** — полный инвентарь: группы `group_<имя>` с секциями
(`home`/`config`/`sessions` у агентов, `dirs`/`files`, `paths`) и `desc:`;
**`configs/selection.yaml`** — галочки по умолчанию, дерево повторяет чеклист
(`group_<имя>.on` + вложенные пути `путь: true/false`).
**`configs/exclude_dirs.yaml`** — исключения: `tar:` шаблоны для всех сегментов
(без хвостового `/`), `appimages.skip_zero_size` — битые/пустые AppImage не
переносятся автоматически.
При инициализации на новой системе ИИ-агент обязан:
1. проверить/актуализировать пути в `configs/inventory.yaml` под новую систему (они могут
   отличаться: версии агентов, новые каталоги сессий — особое внимание
   `group_agents.sessions`; старые значения могут быть неактуальны, пример:
   бэкап `agent-sessions-20261013_18443/logs/sessions` — путь умер);
2. пересмотреть `configs/selection.yaml` под новую систему (что тяжёлое/опциональное);
3. новый путь → сразу добавить описание в `desc:` configs/inventory.yaml
   (`путь: что в каталоге`), иначе в чеклисте будет только путь;
4. не хардкодить пути в pack.sh/unpack.sh — только правкой конфигов;
   системные файлы — в `src/`, пользовательские конфиги — в `configs/`;
5. записать итоговые `configs/*.yaml` и показать diff вместе с дефолтами
   чеклиста на подтверждение владельцу.

## Правила

- `configs/mapping.toml` — источник истины для установки: `[packages.<ubuntu-имя>]`
  (`name`, `status` ∈ {native, aur, manual, skip}, команды по ТИПАМ систем
  `arch =` / `debian =`, `url` для manual) и `[programs.<секция>.<тул]`
  (пользовательские CLI: npm/uv/pipx/bin; команда по умолчанию от менеджера,
  можно переопределить `arch`/`debian`; `url` — печатается в отчёте).
  Нет записи → только в отчёт.
- flatpak/manual/appimages НЕ устанавливаются скриптом: unpack печатает названия
  и ссылки в конце (flathub-страницы, url из mapping.toml) — ставь вручную.
- Названия прогонов: `<дата>_<исходная-ос>.tar.gz` (+ `.meta/` рядом),
  берётся из /etc/os-release, чтобы бэкапы до/после переезда не смешались.
  Бандл — мульти-членный gzip (или .tar при --no-compress): любое чтение
  только с `tar --ignore-zeros`.
- Перед распаковкой браузеров убедиться, что пользователь помнит пароль
  старого keyring — иначе пароли в профиле не откроются.
- Внимание: сегмент `agents` содержит креды (~/.zcode/cli/credentials.json,
  данные opencode — db/auth в ~/.local/share/opencode, `.pencil/agent-auth`) —
  SSD с бэкапом держать при себе/шифровать. По умолчанию бэкапятся
  zcode + opencode + pencil (selection.yaml; codex/claude/qoder и пр. — off,
  решение владельца). Конфиг OpenWhispr тоже содержит `auth-token.bin`.
- Прямые ссылки на файлы отчёта давать после каждого шага.
